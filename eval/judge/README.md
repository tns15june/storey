# Judging claims against truth

Code scores what it can: generated sets, planted erasures and stair presence. A finding written in words, from Storey on an audited set or from the baseline anywhere, needs a judge to say which truth item it states. That judging is done blind:

1. `eval.report` writes one match sheet per set and method to `data/eval/sheets/`.
2. `python eval/judge/blind.py data/eval/sheets <folder>` copies each sheet that has claims and truth items with nothing that names its method. Each claim keeps only its sheet and statement, under a neutral id (C01, C02, ...), in an order shuffled by a seed from the sheet's sha256, and the copies are numbered in sha256 order. `<folder>.key.json` maps each copy to its set and method, and each neutral id to the claim's own id. It sits beside the folder, not in it, because the judges are given the folder.
3. `workflow.js` (a Claude Code workflow) gives each copy to two judges, Claude agents working separately, under the rules written at its top: the same problem at the same place, a general claim states nothing, and when unsure, no match. An adjudicating agent rules on every claim where the two differ.
4. `python eval/judge/blind.py --unblind <folder> <rulings.json>`, with the list the workflow returns saved as `rulings.json`, writes `eval/matches/<set>.<method>.json` under each claim's own id, which `eval.report` reads back. It writes nothing if any copy's rulings leave a claim out, rule on one twice, name a truth id the copy does not hold or leave a dispute open, if the rulings answer one copy more than once, or if a mapping it would write is already there. Each mapping carries the sha256 of the sheet it answers, so a claim that changes afterwards makes the report refuse it.

Blinding cannot remove what the claims themselves say. Storey's statement is its finding's title and measured value, and a Storey finding about the whole set has no sheet (`null`); the baseline writes free sentences and always names a sheet.

On 1 November 2026 the judges ruled on 382 claims across 35 sheets and agreed on 371; the adjudicator ruled on the other 11. The copies they saw came from the first `blind.py`, which dropped the method's name but kept each claim's own id (A-01 for Storey, B01 for the baseline) and Storey's severity, numbered Storey's sheet of a set before the baseline's, and wrote its key, which names each copy's method, into the folder the copies were in. So a judge could tell the methods apart, although the `judge` note in each of those mappings says the judges were not shown which method made the claims. Those mappings were not judged again. The Richmond mappings quote an examiner's letter and stay out of this public repository.
